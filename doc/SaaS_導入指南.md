# 企業級排隊系統 (QMS) - SaaS 導入指南

本指南專為準備整合 **Queueing Management System (QMS)** 的企業客戶（租戶）所編寫。
QMS 作為一個強大的 SaaS (Software as a Service) 邊界防護盾，導入的最高指導原則是：**對客戶（租戶）原有的業務系統改動越小越好，並且排隊系統必須作為一道不可繞過的「虛擬大門」**。

導入流程分為以下四個關鍵階段：

---

## 階段一：活動註冊與配置 (事前準備)

在準備舉辦高流量活動（如限量商品秒殺、演唱會搶票）前，您需要先透過 QMS 管理後台進行參數配置。

1. **建立活動**：
   在 QMS 建立一檔活動，系統會核發給您一組唯一的 `tenantId` (例如 `shopee`) 與 `activityId` (例如 `iphone16-sale`)。
2. **評估並設定最大容量 (Max Capacity)**：
   評估您自家訂單系統的極限，決定「允許同時進入系統的最大人數」。
   * **最大化吞吐量 (Capacity > 1)**：若您的資料庫有良好的防超賣機制，可將容量設為壓測極限值（例如 500）。QMS 保證無論有多少人排隊，您的系統同時最多只會收到 500 個併發請求。
   * **嚴格的序列化 (Capacity = 1)**：若您的系統較舊或不具備執行緒安全 (Thread-Safe)，請設為 1，強制執行一進一出的序列化處理。
3. **選擇放行模式**：
   支援「自動放行 (AUTOMATIC)」或「手動放行 (MANUAL)」模式，並可開啟「每日自動歸零」功能。

---

## 階段二：前端流量攔截 (Virtual Waiting Room)

當活動開始，成千上萬的消費者湧入時，必須確保這波海量流量由 QMS 來承受。

1. **改道 (Redirect)**：
   電商平台的前端不應直接呼叫自身的結帳/搶購 API，而是將使用者**導向 QMS 的排隊頁面**（或透過 `iframe` 將 QMS 的排隊元件嵌入至您的網頁中）。
2. **領取號碼牌 (Enqueue)**：
   消費者在 QMS 完成取號，並開始看到目前排隊進度與等候人數。此階段的連線壓力 100% 由 QMS 的 Redis 與 WebFlux 承受，您的伺服器不會收到任何流量。
3. **心跳維持 (Heartbeat)**：
   QMS 前端會每 10 秒自動發送心跳封包。若消費者中途關閉網頁超過 30 秒，QMS 將啟動「斷線回收機制」，自動釋放該名額。

---

## 階段三：安全放行與驗證 (Handover)

這是確保排隊系統不被惡意腳本 (Bots) 繞過的最重要環節！

1. **獲得放行憑證 (Queue Token)**：
   當輪到該名消費者時，QMS 會發放一組加密且不可偽造的 **Queue Token (等候憑證)**，並將消費者導回電商的實際結帳頁面，並在網址或 Header 中附帶該 Token。
2. **送出訂單**：
   消費者在您的電商頁面填寫資料，按下「確認結帳」時，將訂單資料與 Queue Token 一併送到您自家的後端伺服器。
3. **防繞過驗證 (Token Validation)**：
   您的後端收到訂單的第一件事，必須**呼叫 QMS 的 API 檢查這個 Queue Token 是否合法且已被放行**。
   * **驗證成功**：接受訂單，開始扣庫存與刷卡。
   * **驗證失敗或無 Token**：直接拒絕請求 (HTTP 403 Forbidden)，防止駭客繞過排隊系統直接打 API。

---

## 階段四：動態削峰填谷 (Feedback Loop)

為了讓 QMS 知道何時可以放下一批人進來，您需要實作「容量釋放 (Capacity Release)」機制。

1. **處理業務**：
   您的後端開始處理剛才放行進來的訂單。
2. **釋放容量 (Release Capacity)**：
   當訂單處理完畢（無論是成功結帳、刷卡失敗、或是使用者猶豫太久訂單過期），您的後端必須**非同步地**通知 QMS 釋放空位。
   
   支援兩種通知方式：
   * **Kafka Event (推薦)**：發送訊息至 `qms.downstream.task.completed` Topic。
   * **HTTP API**：呼叫 `POST /api/v1/capacity/release`。
   
   *通知內容範例：*
   ```json
   {
     "tenantId": "shopee",
     "activityId": "iphone16-sale",
     "ticketNumber": 36,
     "releasedAmount": 1
   }
   ```
3. **自動遞補**：
   QMS 收到通知後，發現容量空出 1 個位子，立刻觸發自動叫號機制，放行排在最前面的使用者進入您的系統，實現完美的**動態削峰填谷**。

---

### 總結

導入 QMS 系統，客戶不需大改原有的巨石架構。只需完成：
1. **前端**：把原本直連後端的按鈕，改為導向 QMS 領取號碼牌。
2. **後端**：在核心 API 前新增一個 Interceptor（攔截器）檢查 Queue Token，並在處理完畢後發送一個非同步通知還原容量。

完成以上兩步，您的系統即可瞬間獲得抵禦百萬級突發流量的能力！
